Shared component reuse No dedicated component library — UI scattered inside src/modules/* and src/layout/components/, no atomic categorization, no Storybook. Dedicated atomic-design system (atoms/molecules/organisms/layouts/templates), Storybook per component, reuse-before-duplicate, human approval on breaking changes.‡ TECH-142–147
Component structure Container/presentational split already present informally (e.g. CartContainer.js + components/) — no size limit, no rule against prop drilling. Same pattern formalized: 300-line cap per file, feature-scoped context/ instead of prop drilling, restricted to feature-internal state only. TECH-138–141
Decoupling — shared UI from features UI pieces embedded inside each module or the layout folder, no separately versioned package — nothing forces reuse. Shared design-system component library lives in its own repo, consumed by every repo via Module Federation exposes. TECH-142–147
